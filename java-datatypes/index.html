Java Datatypes: The Ultimate Reference

An interactive guide covering primitive, wrapper, collection, and memory management concepts.

⚡ Primitive Datatypes (Stack Memory)

Primitive data types store their values directly on the stack. They are simple, predefined, and offer high performance with fixed sizes.

  • boolean: Represents a single bit (`true`/`false`), though JVM-dependent, often stored as a byte.
  • byte: 8-bit signed integer (-128 to 127).
  • short: 16-bit signed integer (-32,768 to 32,767).
  • int: 32-bit signed integer. The default integer type.
  • long: 64-bit signed integer for very large numbers.
  • float: 32-bit single-precision floating-point number (IEEE 754).
  • double: 64-bit double-precision floating-point number (IEEE 754), offering higher precision.
  • char: 16-bit unsigned Unicode character.

📦 Wrapper Classes (Heap Memory)

For every primitive type, Java provides a corresponding wrapper class to enable its use as an object (e.g., in Collections). This process is called autoboxing, and the objects are stored on the heap.

📂 Data Structures & Collections (Heap Memory)

These reference types are objects stored dynamically on the heap, referencing other objects or data structures.

String

An immutable object internally using a byte[] array. Stored in the heap, with literals using the String Constant Pool for memory optimization.

Arrays

Fixed-size, contiguous blocks of memory on the heap. Stores values directly (for primitives) or references (for objects).

ArrayList

A resizable array backed by an Object[]. Resizing involves creating a new, larger array on the heap and copying elements over. Fast random access, slow insertions/deletions.

LinkedList

A doubly-linked list where each Node object points to the next and previous nodes. Nodes are non-contiguous on the heap. Fast insertions/deletions, slow random access.

Vector and Stack

Legacy synchronized classes. Vector is a synchronized ArrayList, and Stack extends Vector. Slower due to synchronization overhead.

HashMap / HashSet

Both use a hash table (array of buckets on the heap). Collisions use a linked list or, since Java 8, a balanced binary search tree. HashSet stores elements as HashMap keys.

TreeMap / TreeSet

Both use a red-black tree for balanced, sorted storage. TreeMap stores sorted key-value pairs, while TreeSet stores unique, sorted elements.

PriorityQueue

A queue that orders elements by priority. Implemented as a binary heap backed by a dynamic array.

ArrayDeque

A modern, fast, non-synchronized double-ended queue, backed by a resizable array.

Enum

A special class type where constants are public static final references to enum objects on the heap.

Record (JDK 16+)

An immutable data-carrier class with final fields. Stored on the heap with optimized memory layout.

🔄 Concurrency and Thread Safety

Topics around managing and ensuring thread safety are crucial for robust application development.

synchronized

Used to control access to shared resources by multiple threads. It provides mutual exclusion by allowing only one thread to execute a synchronized block or method at a time.

volatile

Guarantees that changes to a variable by one thread are immediately visible to all other threads. It ensures visibility but not atomicity for compound operations (e.g., i++).

  • Hashtable: Synchronizes on the entire map, leading to poor performance with high concurrency.
  • ConcurrentHashMap: Uses fine-grained locking (divides data into segments), allowing multiple threads to read and write concurrently. Significantly faster for concurrent access.
  • Fail-Fast: Iterators (e.g., ArrayList) throw ConcurrentModificationException if the collection is structurally modified during iteration.
  • Fail-Safe: Iterators (e.g., CopyOnWriteArrayList) operate on a copy of the collection, so modifications to the original don't affect the iterator.

Memory Model: Stack vs Heap

Understanding the fundamental difference in how Java manages memory is critical. The Stack is for method execution and local variables, while the Heap is for objects.

Stack Memory

(Fast, Fixed Size, LIFO)

(contains local var references)
temp() method call
(stores its own primitives/references)

... Each thread has its own stack

Heap Memory

(Slower, Dynamic Size)

(Object data)

(Object data)

... Shared among all threads

Key Differences:

  • Stack: Stores method calls and references to objects. Automatically managed by the JVM. Fast access but limited size.
  • Heap: Stores the actual objects. Managed by the Garbage Collector. Slower access but much larger.

❓ Quick View: Q&A

Essential questions and concise answers on core Java topics for quick revision.

  • == Operator: Compares object references (memory addresses). It checks if two variables point to the exact same object in memory.
  • .equals() Method: Compares the actual content or value of the objects. It can be overridden to provide custom comparison logic.
  • Rule of thumb: Use == for primitives. Use .equals() for objects to compare value, unless you need to check for the same memory location.
  • String: Immutable and final. New objects are created for any modification. It is thread-safe and stored in the string pool for literals.
  • StringBuilder: Mutable and not thread-safe. Faster than StringBuffer for single-threaded environments because it is not synchronized.
  • StringBuffer: Mutable and thread-safe (methods are synchronized). Slower than StringBuilder due to the overhead of locking.
  • Security: Critical for storing sensitive information like passwords, as the value cannot be altered.
  • Caching: Its hashcode is cached at creation, making it an efficient key for HashMaps.
  • Thread Safety: The immutability ensures it is inherently thread-safe, as its state cannot change after construction.
  • String Pool: Enables memory optimization by reusing identical string literals.
  • ArrayList: Backed by a dynamic array. Best for quick element retrieval (random access). Manipulations like insertion/deletion in the middle are slow due to element shifting.
  • LinkedList: Implemented as a doubly-linked list. Best for frequent insertions and deletions, especially at the beginning or middle. Retrieval by index is slower as it must traverse from the start or end.
  • Uses a hash table (an array of buckets). The hashCode() of the key determines the bucket index.
  • A collision (different keys with the same hash) is handled by chaining entries in a linked list within the bucket.
  • Since Java 8, long linked lists convert to balanced binary search trees to improve performance from O(n) to O(log n).
  • Comparable: Defines a "natural ordering" for a class. Must be implemented by the class itself (e.g., String and wrapper classes). Uses the compareTo() method.
  • Comparator: Defines a custom sorting order. It is a functional interface that can be implemented externally to compare two objects. Uses the compare() method.
  • Abstract Class: Can have both abstract (no body) and concrete methods. Can have constructors and instance variables (final, non-final, etc.). A class can only extend one abstract class.
  • Interface: Defines a contract for behavior. (Pre-Java 8) only abstract methods and public static final variables. (Java 8+) allows default and static methods. A class can implement multiple interfaces.
  • Usage: Use an abstract class when you have related classes sharing a common base with shared implementation. Use an interface to define behavior that can be implemented by unrelated classes.
  • Checked Exceptions: Must be explicitly handled using try-catch or declared with throws. Inherit from Exception. E.g., IOException.
  • Unchecked Exceptions: Do not require explicit handling. Inherit from RuntimeException. Represent programming bugs. E.g., NullPointerException.
  • final keyword: Declares constants, prevents method overriding, or prevents class inheritance.
  • finally block: Guarantees code execution in exception handling, regardless of whether an exception was thrown.
  • finalize() method: Deprecated and unreliable. Called by GC before an object is destroyed. Do not rely on it.
  • NEW: Created but not started.
  • RUNNABLE: Executing or ready to execute.
  • BLOCKED: Waiting for a monitor lock.
  • WAITING: Waiting indefinitely for another thread's action.
  • TIMED_WAITING: Waiting for a specified time interval.
  • TERMINATED: Finished execution.
  • Thread.sleep(): Pauses the current thread without releasing locks. Time-dependent.
  • Object.wait(): Pauses the current thread and releases its lock. Time-independent, requires notify() or notifyAll() to resume, and must be called within a synchronized block.

You can request a garbage collection run by calling System.gc() or Runtime.getRuntime().gc(), but the JVM decides if and when to execute it. Its behavior is not guaranteed.

A memory leak occurs when objects that are no longer needed are still reachable from a root object. The Garbage Collector only reclaims objects that are unreachable. For example, a long-lived static Map can hold references to unneeded objects, preventing their collection.

  • map(): Applies a function to each element and returns a stream of the results. The size remains the same.
  • flatMap(): Applies a function that returns a stream for each element. The resulting streams are flattened into a single, unified stream. Useful for processing nested collections.
  • Optional.isPresent(): Returns true or false to check for a value's presence, often used with an if/else.
  • Optional.ifPresent(): Takes a Consumer and executes it only if a value is present, avoiding explicit null checks and encouraging a functional approach.
  • Functional Interface: An interface with exactly one abstract method.
  • @FunctionalInterface Annotation: Provides compile-time checks to ensure the interface meets the criteria.
  • IoC: A design principle where a framework controls the flow of a program.
  • DI: A specific implementation of IoC where objects receive dependencies from an external source (e.g., Spring container), promoting loose coupling.
  • Purpose: Restricts a class to a single object instance.
  • Implementation: Can be done via lazy or eager initialization, or more robustly with an enum.
  • Spring: A comprehensive, modular framework requiring more manual configuration.
  • Spring Boot: An opinionated framework simplifying Spring setup with minimal configuration, embedded servers, and "convention over configuration."
  • Fail-Fast: Iterators (like ArrayList.iterator()) that throw a ConcurrentModificationException immediately if the collection is structurally modified during iteration (except by the iterator's own methods).
  • Fail-Safe: Iterators (like ConcurrentHashMap.iterator()) that operate on a copy of the collection, so modifications to the original do not affect the iterator. They do not throw ConcurrentModificationException.
