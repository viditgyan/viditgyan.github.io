🧭 Design Framework

Structure your design discussions to cover requirements, capacity, architecture, and trade-offs.

1. Clarify Requirements

  • Functional scope, MVP vs full solution.
  • Non-functional: latency, availability, durability, compliance.
  • Traffic profile: requests per second, data size, peak vs steady-state.

2. Define Interfaces & API

  • External APIs, internal service boundaries.
  • Data contracts, payload size, versioning.
  • Authorization/authentication needs.

3. High-Level Architecture

  • Identify major components (frontend, backend, storage, caches, messaging).
  • Define data flow from ingress to storage to clients.
  • Use diagrams to illustrate interactions and replication.

4. Deep Dive on Key Areas

  • Data storage modeling.
  • Scaling strategies (horizontal, vertical, partitioning).
  • Consistency models, caching, queueing, failover.

5. Consider Reliability & Operability

  • Monitoring, logging, alerting.
  • Deployment strategy, rollback plans, auto-scaling.
  • Security, compliance, data privacy.

6. Evaluate Trade-offs

  • Latency vs consistency, complexity vs time-to-market.
  • Cost implications of architecture choices.
  • Evolution over time (initial vs future phases).

🧱 Platform Building Blocks

Understand core components you’ll combine when designing systems.

Load Balancers

Traffic
  • L4 vs L7, health checks, SSL termination.
  • Consistent hashing vs round robin vs least connections.
  • Global load balancing (Anycast, GSLB).

Caches

Performance
  • Multi-tier: client, edge/CDN, service, database caches.
  • Patterns: cache-aside, read/write-through, write-back hybrids.
  • Invalidation & stampede control: explicit delete, event-driven, jitter, stale-while-revalidate.

Datastores

Persistence
  • Relational (PostgreSQL/MySQL) vs NoSQL (Cassandra, DynamoDB) vs NewSQL (CockroachDB).
  • Replication, sharding, quorum reads/writes, schema evolution.
  • Select engines based on query model, latency, durability, and consistency needs.

Queues & Streams

Decoupling
  • Message brokers (RabbitMQ, SQS) vs log streams (Kafka, Pulsar, Kinesis).
  • Delivery semantics (at-least/exactly-once), ordering, consumer groups.
  • Backpressure, DLQs, replay strategy, schema registry governance.

Object Storage & CDN

Durability
  • Immutable blobs (S3, GCS) for assets, backups, ML artifacts.
  • Versioning, lifecycle policies, replication across regions or availability zones.
  • Integrate with CDN for signed URLs, cache-busting, regional performance.

Search & Indexing

Discovery
  • Text search (Elasticsearch, OpenSearch) and vector search (Pinecone, Weaviate).
  • Denormalised indices, relevancy tuning, synonym management.
  • Ingestion via CDC, pipelines, or change streams; handle reindex and backfill.

Observability Stack

Operations
  • Metrics (Prometheus, CloudWatch), tracing (OpenTelemetry), logs (ELK, Loki).
  • Alerting on golden signals, runbooks, incident tooling (PagerDuty, Opsgenie).
  • Error budgets, chaos drills, automated diagnostics.

🧩 Design Patterns

Reusable blueprints that appear across large-scale systems. Choose intentionally—every pattern introduces trade-offs.

CQRS

Read/Write Split
  • Separate read and write models to optimise latency vs consistency.
  • Combine with read replicas or materialised views for low-latency queries.
  • Manage eventual consistency on read side and schema drift between models.

Event Sourcing

Immutable Log
  • Persist events, rebuild state via projections, enable time-travel debugging.
  • Requires snapshotting, replays, and careful event versioning.
  • Great for auditability and CQRS read models; ensure GDPR deletion strategy.

Saga / Orchestration

Distributed Transactions
  • Coordinate multi-service workflows via choreography (events) or orchestration (controller).
  • Define compensating actions, timeouts, and idempotent handlers.
  • Instrument saga metrics to detect stuck or failing instances.

Bulkheads & Circuit Breakers

Resilience
  • Isolate resource pools per dependency/tenant to contain blast radius.
  • Trip circuits on failures, recover via half-open probes, combine with retries/backoff.
  • Expose load shedding fallbacks (cached or degraded responses).

Strangler Fig

Modernisation
  • Incrementally route traffic from legacy to new services via edge layer.
  • Keep data flows in sync—dual writes or event bridges until cut-over.
  • Observe KPIs on both stacks before decomposing the monolith.

Edge & Offline First

Global UX
  • Leverage CDNs, edge compute, or P2P sync to reduce round trips.
  • Conflict resolution via CRDTs, OT, or last-write-wins semantics.
  • Secure data at rest on device; plan for key revocation and remote wipe.

⚖️ Trade-off Guides

Frame conversations with stakeholders using these common axes; document your rationale.

Dimension Preferred When Upside Downside Probe
Consistency vs Availability CP (strong consistency) Deterministic reads, simpler business rules. Higher latency, partition-sensitive outages. Can users tolerate stale data? What’s the outage profile?
Latency vs Cost Edge/CDN replication Low latency, global reach. Complex invalidation, higher storage spend. Is content cacheable? How fast does it change?
Build vs Buy Managed service Reduced ops burden, faster launch. Vendor lock-in, limited customisation. Is differentiation strategic? Does compliance allow outsourcing?
Single vs Multi Region Single region Simpler data model, lower cost. Worse latency for distant users, larger blast radius. What are RTO/RPO targets? Any data residency rules?
Monolith vs Microservices Modular monolith Fast development, easy refactor, single deploy pipeline. Scale bottlenecks, slower independent releases. Do teams align to modules? How often do boundaries change?

📈 Capacity Planning Toolkit

Stay ahead of growth—capacity work is cheaper than firefighting.

Traffic Forecasting

Demand
  • Translate MAU/DAU into RPS, concurrent sessions, peak factors.
  • Account for seasonality, marketing pushes, incident scenarios.
  • Validate with synthetic and replay tests before big launches.

Resource Headroom

Resilience
  • Target ≥30% headroom for CPU, memory, IO at P95 load.
  • Design N+1 or N+2 capacity, test zone evacuation regularly.
  • Codify autoscaling triggers, warm-up procedures, manual overrides.

Storage Growth

Data
  • Track dataset growth, compression ratios, churn rates.
  • Introduce tiering, compaction, and retention guardrails.
  • Plan migration/partition strategies before limits are hit.

Cost Guardrails

Finance
  • Monitor cost per request/tenant; alert when budgets exceed thresholds.
  • Use rightsizing, reserved/spot instances, autoscaling schedules.
  • Make trade-off decisions transparent to product & finance partners.

🧪 Reference Architectures

Apply patterns to well-known prompts—use them as scaffolding, not final answers.

Realtime Feed / Timeline

  • Hybrid fan-out (write for influencers, read for long-tail).
  • Write pipeline → Kafka → fan-out workers → cache + cold store.
  • Ranking service with feature store, eventual consistency tolerances.

Chat / Messaging

  • Gateway fan-out (WebSocket/gRPC), presence service, typing indicators.
  • Partition messages by conversation, ack + retry semantics.
  • End-to-end encryption, spam/abuse throttling, offline sync.

Ride Sharing / Dispatch

  • Geo-spatial index (H3, R-Tree) for nearby driver lookup.
  • Streaming ETL for ETA prediction, surge pricing, telemetry.
  • Dual write to transactional DB + analytics/ML features.

Video Streaming

  • Ingest → transcode pipeline (FFmpeg/MediaConvert) → global object storage.
  • CDN edge auth, ABR manifests, QoE feedback loop.
  • DRM, geo-restrictions, watermarking, device compatibility matrix.

E-commerce Checkout

  • Inventory reservation + idempotent payment service.
  • Saga for order orchestration (payment, fulfillment, notifications).
  • Fraud scoring, rate limiting, feature flags for rollback.

Analytics Pipeline

  • Ingestion gateway → stream/batch ETL → lakehouse/warehouse (Snowflake, BigQuery, Iceberg).
  • Deduplication, late-arriving events, schema registry.
  • Serving layer (Presto/Trino/Druid) + semantic cache + access governance.

❓ Interview Checklist

Before wrapping, ensure you’ve addressed these pillars. Missing one is a common interview pitfall.

Product & Users

  • Who are the primary users? What are success metrics?
  • What workloads are bursty vs steady?
  • Any SLAs/SLIs for latency, availability, data freshness?

Data & Storage

  • Entity relationships, access patterns, retention policies.
  • Consistency model per operation, idempotency, conflict resolution.
  • Backup/restore, migration, schema evolution, GDPR deletes.

Scalability & Performance

  • Peak load assumptions, headroom, load test results.
  • Caching layers, partition strategy, autoscaling configuration.
  • Cold start plans, rate limiting, backpressure signals.

Reliability & Operations

  • SLOs/error budgets, monitoring, alerting, incident response.
  • Deployment strategy, rollback, blue/green or canary approach.
  • DR/BCP plans, chaos and game-day cadence.

Security & Compliance

  • AuthN/Z design, secrets management, audit logging.
  • Data classification, encryption at rest/in transit, key rotation.
  • Regulatory needs (GDPR, HIPAA, PCI, SOC2) and data residency.

Evolution & Trade-offs

  • Phase-wise roadmap, iteration strategy, feature flags.
  • Open risks, assumptions, follow-up experiments or metrics.
  • Communication plan with stakeholders (eng, product, infra).
System design is iterative—document assumptions, measure outcomes, and evolve architecture as scale and requirements shift.
