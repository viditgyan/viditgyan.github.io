📘 What Are Anti-Patterns?

An anti-pattern is a repeated solution that looks convenient but erodes performance, scalability, or correctness. Recognising them early lets you intervene before they reach production or consume costly incident cycles.

Traits

  • Familiar workaround to ship quickly.
  • Hidden cost: performance, maintainability, or security debt.
  • Often detectable via metrics (latency spikes, load, error rates).

Typical Sources

  • Knowledge gaps (e.g., ORM abstraction hides SQL realities).
  • Process shortcuts (lack of reviews, testing, or instrumentation).
  • Premature optimisation or over-engineering.

Detection Toolkit

  • APM traces and slow-query logs.
  • Linters, static analysis, architecture decision records.
  • Load testing, chaos experiments, SLA/SLO monitors.

Remediation Loop

  • Spot the anti-pattern → Prioritise impact.
  • Apply targeted solution & refactor.
  • Institutionalise learning via playbooks, lint rules, or design reviews.

🗄️ Database & ORM Anti-Patterns

Data access anti-patterns appear even in mature stacks—especially when ORMs abstract SQL or when datasets grow faster than expected.

N+1 Query Problem

Performance Data Access

An initial query fetches a list of records (N), and for each record another query is executed, producing N additional round-trips. Latency scales linearly with record count.

// Example: ORM fetching comments for each post\nconst posts = await Post.findAll();\nfor (const post of posts) {\n const comments = await post.getComments(); // executes one query per post\n}\n
Signals: Sudden latency spikes when result set grows, database connection pool saturation, repeated patterns in slow-query logs.
Solutions:
  • Use eager loading / IN query (e.g., include, JOIN, preload).
  • Batch lookups with data loaders or query builders (SELECT ... WHERE id IN (...)).
  • Audit ORM defaults; add linters/tests to catch nested async calls.

Missing or Misused Indexes

Performance Scalability

High-cardinality columns lacking indexes cause full table scans. Conversely, low-selectivity indexes consume space yet rarely used.

  • Detection: EXPLAIN plans, pg_stat_statements, SQL Server DMVs.
  • Fix: Add B-Tree indexes for selective columns, partial indexes for filtered queries, composite indexes respecting predicate order.
  • Guardrails: Weekly index usage reports; schema migration CI checks for redundant indexes.

Chatty Pagination (OFFSET/LIMIT)

API Data

Using offset-based pagination on large tables causes the database to walk past skipped rows repeatedly.

Alternatives:
  • Keyset pagination (seek method) using indexed columns.
  • Remember user state with stable cursors (e.g., GraphQL Relay).
  • Add covering indexes to align with sort predicates.

Storing Derived Data Without Revalidation

Consistency

Materialised/denormalised columns drift from source when recalculation is missing.

  • Recompute via triggers, CDC pipelines, or background jobs with checksum comparison.
  • Store derivation metadata and last-updated timestamps.
  • Use materialized views with REFRESH policies, not hand-rolled tables.

🌐 API & Integration Anti-Patterns

APIs mediate between systems; anti-patterns here amplify latency, increase cost, or expose fragile coupling.

Chatty API (Fine-Grained Calls)

Latency Network

Client performs dozens of sequential requests to build one view (e.g., fetching every resource individually).

Fixes:
  • Aggregate endpoints or GraphQL queries with dataloaders/batching.
  • Use HTTP/2 multiplexing or gRPC streaming to reduce connection overhead.
  • Cache stable responses at gateway/CDN layers.

God Endpoint / Overfetching

Maintainability

Single endpoint returns massive payloads for all clients, most fields unused.

  • Adopt projection (GraphQL selection sets, sparse fieldsets, REST resource decomposition).
  • Monitor response size percentiles (P95) and enforce budgets.
  • Version APIs with backward compatibility guarantees; retire fields gradually.

Ignoring Idempotency

Reliability

Retrying non-idempotent operations (e.g., payment capture) causes duplicate side effects.

Impact: Double charges, inconsistent state, compensating transactions.
Mitigation:
  • Idempotency keys with deduplication store (Redis, DynamoDB, SQL unique constraints).
  • Design POST endpoints to handle duplicate payloads gracefully.
  • Implement distributed locks or transactional outbox for multi-step workflows.

Tight Coupling to Upstream Schema

Integration

Client code assumes upstream data shape; any provider change breaks consumers.

  • Adopt Backwards-compatible schema evolution (additive changes, contract tests, consumer-driven contracts).
  • Use adapters or anti-corruption layers for third-party APIs.
  • Mock with real contract fixtures in CI/CD.

🏗️ Application & Architecture Anti-Patterns

These anti-patterns affect readability, extendability, and system resilience.

God Object / Blob

Maintainability

Single class/module accumulates dozens of responsibilities, making changes risky.

Solutions:
  • Identify bounded contexts; split into cohesive service classes or modules.
  • Introduce interfaces or ports/adapters to decouple infrastructure concerns.
  • Add unit tests around extracted behaviours before refactoring.

Shotgun Surgery

Regressions

Small change requires edits in many places (due to duplicated logic or cross-cutting concerns).

  • Centralise shared logic (utility modules, services, or policies).
  • Apply aspect-oriented techniques (middleware, interceptors) for cross-cutting concerns.
  • Set up automated tests covering multiple layers (contract + integration).

Premature Optimisation

Team Productivity

Optimising obscure paths before validating requirements or usage.

Smells: Micro-optimised code without benchmarks, complex caching layers before measuring baseline.
Validate with profiling data; ship simple design, measure, then optimise targeted hotspots.

Circular Dependencies

Architecture

Modules depend on each other, complicating builds, deployment, and reasoning.

  • Enforce dependency direction (Clean Architecture, Hexagonal).
  • Introduce domain services or event mechanisms for cross-module communication.
  • Use dependency graphs/linters (import-linter, depcheck) in CI.

🛡️ Operations, Delivery & DevOps Anti-Patterns

Operational anti-patterns undermine reliability and delivery speed.

Manual, Dark Deployments

Deployment

Releases triggered manually without reproducible scripts or visibility.

  • Adopt GitOps or CI-driven pipelines; use infrastructure as code (Terraform, Pulumi).
  • Enable canaries/feature flags for incremental rollout.
  • Record deployment metadata and link to incidents/change management.

Snowflake Servers

Reliability

Manually configured hosts that drift from desired state.

Remedy:
  • Immutable infrastructure (containers, golden AMIs) or configuration management (Ansible, Chef).
  • Run configuration drift detection (AWS Config, Puppet inspector).
  • Document provisioning via automated runbooks.

No Observability / Blind Spots

Incident Response

Missing tracing, metrics, or logs; issues only seen by end-users.

  • Define SLOs and error budgets; instrument golden signals (latency, traffic, errors, saturation).
  • Adopt structured logging and distributed tracing (OpenTelemetry).
  • Run game days/chaos experiments to validate alerts.

Hero Culture

Team Health

A few individuals own tribal knowledge; burnout risk and single points of failure.

  • Rotate on-call duties, pair program, record design docs.
  • Cross-train via shadowing and mob debugging.
  • Encourage blameless postmortems with shared action items.
